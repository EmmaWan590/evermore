# ARCHITECTURE — Evermore

## 1. Shape

A single-page, client-only application. There is no backend, no API, no
service other than the static file host. All state of consequence lives in
IndexedDB on the device; all state of convenience (language, appearance,
whether the intro has played) lives in `localStorage` / `sessionStorage`.

```
React 19 ── Context ── pages ── components
                    │
                    └── repository (async API) ── idb ── IndexedDB
```

## 2. Stack

| Concern | Choice |
| --- | --- |
| Build | Vite 8 (`@vitejs/plugin-react`), TypeScript 7 (`tsc --noEmit`) |
| UI | React 19, React Router 7 (`BrowserRouter`) |
| Styling | Tailwind CSS 4 via `@tailwindcss/vite`, tokens in `@theme` |
| Fonts | `@fontsource-variable/inter`, `@fontsource-variable/playfair-display` |
| Storage | `idb` 8 wrapper over IndexedDB |
| PWA | `vite-plugin-pwa` 2 (generateSW / Workbox) |
| Tests | Vitest 5 (configured; no suites yet) |

## 3. Layers

```
src/data/types.ts        domain types + runtime guards (isCategory, isObjectKind)
src/data/db.ts           schema, open, persistence request, storage estimate
src/data/repository.ts   the only module that touches idb
src/data/localRepository.ts  implementation of Repository
src/data/AppData.tsx     React context: cached lists + mutations that refresh
src/features/attachments/image.ts   decode → canvas → JPEG full + thumb
src/features/attachments/useAttachmentUrl.ts  Blob → object URL, revoked on unmount
src/features/backup/backup.ts       export/import one JSON file
src/i18n/                en + zh dictionaries, `useI18n()`
src/theme/appearance.tsx `void` / `deep`, sets `data-appearance` and theme-color
src/lib/date.ts          local-day parsing/formatting, month keys, sort keys
src/lib/utils.ts         `cn`, `newId`
```

Pages never import `idb` or the repository directly for reads: they consume
`useAppData()`, whose `entries` / `objects` / `objectMap` are refreshed after
every mutation. Writes always go through the context so the cache cannot drift.

## 4. Data model

```ts
Entry {
  id, title, content, category: 'wealth'|'health'|'journey'|'memories'|null,
  eventDate: 'YYYY-MM-DD'|null, location: string|null,
  objectIds: string[], attachmentIds: string[],
  createdAt: ISO, updatedAt: ISO
}

EverObject { id, kind: 'person'|'place'|'thing'|'idea', name, createdAt }

AttachmentMeta { id, entryId, mimeType, fileName, size, width, height, createdAt }
AttachmentRecord extends AttachmentMeta { blob: Blob /*1600px*/, thumb: Blob /*320px*/ }
```

An entry is *dated* by `eventDate` when present, otherwise by the day its
`createdAt` fell on — see `entryDay()`. Sorting and month grouping both derive
from that single function, so a back-dated entry lands where it belongs.

## 5. IndexedDB

Database `evermore`, version 1, four stores:

| Store | Key | Indexes |
| --- | --- | --- |
| `entries` | `id` | `by-created` on `createdAt` |
| `objects` | `id` | — |
| `attachments` | `id` | `by-entry` on `entryId` |
| `meta` | `key` | — |

Deleting an entry deletes its attachment records in the same transaction;
deleting an object strips its id from every entry that referenced it (the
entries themselves stay). A single failed open resets the memoised promise so a
retry is possible.

`requestPersistentStorage()` asks once, silently, after the first successful
read. `storageEstimate()` feeds the Profile panel. Neither is a guarantee, and
the UI says so.

## 6. Photos

`processImage(file)` decodes with `createImageBitmap` (`imageOrientation:
'from-image'`, falling back to `<img>` for older Safari or exotic codecs),
draws twice at 1600 px and 320 px on the long edge, and encodes **WebP** at
0.82 / 0.78 — JPEG is used only when the browser quietly falls back to PNG.
Files that are not images, or are over 20 MB, are rejected before decoding.
Six photos per entry.

Only thumbnails are requested while browsing; the full blob is read when a
photo is opened in the lightbox. `useAttachmentUrl` owns every object URL it
creates and revokes it on unmount, so browsing a long timeline does not leak
memory.

## 7. Backup format

```json
{ "app": "evermore", "schemaVersion": 1, "exportedAt": "...",
  "entries": [...], "objects": [...],
  "attachments": [{ "...meta", "data": "data:image/webp;base64,..." }] }
```

Only the full image is exported; thumbnails are regenerated by `makeThumb()`
on import, which keeps a backup roughly the size of the photos themselves.
Restore replaces everything (`importAll`) inside one transaction and drops
attachment ids that the bundle did not contain, then the context refreshes. The
import is confirmed first, because it is destructive.


## 8. Routing

`BrowserRouter` with `basename` taken from `import.meta.env.BASE_URL`, so the
same build works at `/` and at `/evermore/`.

| Path | Screen | Notes |
| --- | --- | --- |
| `/` | Intro gate | Plays the opening once per session, then redirects to `/universe` |
| `/welcome` | Welcome | Reachable again from Profile → "Play the opening again" |
| `/universe` | Universe | Four worlds with counts |
| `/timeline` | Timeline | `?category=wealth|health|journey|memories` |
| `/create` | Create | |
| `/entry/:id` | Entry detail | Edit, delete, lightbox |
| `/entry/:id/edit` | Create in edit mode | Prefills from the existing entry |
| `/explore` | Explore | Four kinds |
| `/explore/:kind` | Objects of one kind | `?open=<objectId>` shows one object |
| `/profile` | Profile | |
| `*` | Not found | |

A `ScrollToTop` effect resets scroll on every pathname change. The router sits
inside the providers, so a route change never remounts data or language state.

## 9. PWA and deployment

- `vite-plugin-pwa` with `registerType: 'autoUpdate'`, `generateSW`, precaching
  all js/css/html/svg/png/woff2 output; `navigateFallback: 'index.html'`.
- Manifest: standalone, portrait, dark theme colour, 192/512 icons plus a
  maskable 512 (cluster scaled to the 50 % safe zone).
- `spaFallback()` copies `index.html` to `404.html` at the end of the build —
  the only reason deep links survive on GitHub Pages.
- `base` is `process.env.VITE_BASE ?? '/'`. CI passes
  `VITE_BASE: /${{ github.event.repository.name }}/`.
- Icons are generated by `scripts/make-icons.mjs` (zlib + hand-written PNG
  chunks); no image tooling is installed.

## 10. Decisions and trade-offs

| Decision | Why | Cost |
| --- | --- | --- |
| IndexedDB, not `localStorage` | Blobs, size, transactions | More code; async everywhere |
| Store blobs, not base64 | Half the space, no re-encode on read | Export needs base64 conversion |
| Full + thumb per photo | Fast timeline, honest full view | ~1.25× storage of a single size |
| React Context, no state library | Two small lists; a library would be ceremony | Every mutation refreshes both lists |
| Hand-rolled i18n | Two languages, ~120 keys, zero deps | No plural rules; keys are flat |
| `entryDay()` for dating | Back-dating must be first-class | Two sort keys to keep straight |
| No encryption | Out of scope for 1.0; saying so is better than implying safety | Anyone with the device can read it |
| CSS/SVG animation only | Nothing to ship, nothing to hydrate | Complex sequences stay simple |
| Object kinds fixed at four | Explore stays legible | No custom kinds |
